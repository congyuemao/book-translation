# 阶段 4：引文核查

外文书里的引文，很多是从中文或别的语言转译过来的。如果把英文引文再直译回中文，得到的是"翻译的翻译"，读者一查就对不上，甚至意思都走样。所以引文要回到能找到的最接近原始的来源。

这一步可能要做很多轮。《天命》做了 45 轮，因为不少材料要靠文献传递。不必一轮做完，但每一轮都要留下清楚的记录。

## 怎么处理一条引文

按顺序往下走，走到能落实的那一步就停：

1. **已有中文原文或已出版中译本**：直接取那里的文字，替换译文。作者引《资本论》，就去找中译本的对应段落，不要自己重译。
   - 作者本来就在引中文材料（毛泽东著作、中文报刊、党史文件），要恢复中文原句。
   - 记下版本、卷次、页码。同一著作有多个中译本的，全书统一用一个（通常是最权威的），除非用户另有指定。
   - 中译文和作者的引法有差异（比如作者删节、改写）时，以中文原文为基础，在章末校注里说明差异，不要硬拼。

2. **没有中译，但能找到外文原文**：回到外文原文（不是作者转引的版本）核对后再翻译。尤其要注意作者引的是英译本、而原文是德文、法文、俄文的情况：优先依原文，至少要核对英译有没有问题。发现作者引错的，照实写校注。

3. **都找不到**：谨慎翻译，紧接引文标 `【原文待核】`（间接转述标在句末），并写明已经查过哪里。

"转引自"也要追。作者转引的二手来源，能追到一手就追到一手，追不到要说明只追到哪一层。

## 证据的强弱不能混用

| `level` | 证据类型 | 说明 |
| --- | --- | --- |
| `scan_original` | 原刊、原书的页图 | 最强 |
| `published_translation` | 已出版中译本 | |
| `contemporary_reprint` | 同期转载 | |
| `later_compilation` | 后出的汇编 | 可能有删改 |
| `digital_typeset` | 电子排印本 | 可能有错字 |
| `web_transcript` | 网络录文 | 可用来定位，要标明性质 |
| `translated_anthology` | 外文译文资料集 | 只能证明"有这回事"，不等于中文原句 |
| `secondary_quote` | 他人转引 | 同上 |

报告和校注要写明用的是哪一级。尤其注意：

- 只找到英文转引，不等于恢复了中文原话。
- 多个网站录文可能同源，不算多份独立证据。
- 全文 OCR 或搜索没命中，只能说"未检索到"，不能说"不存在"。
- 馆藏目录只说明材料在哪，不等于看到了目标文字。
- 落实了引文，不代表证实了作者的历史判断或统计。

**逐字引文要看原始文字。** 摘要式的网页抓取工具会返回模型"还原"的句子，看着像原文，其实可能差几个字。替换前要拿到页面原始文本（比如用 curl 取回后按页面编码解码，中文老网页常是 GB 编码），或者看页图。来源的 `level` 按你实际看到的东西填：看的是网上录文，即使它录的是已出版中译本，也填 `web_transcript`。

## 台账

用脚本从译文里扫出引文，生成固定编号的台账（紧跟注号或待核标记的引号内容，以及引文块）：

```bash
python <skill>/scripts/booktool.py audit-scan .
```

重复运行只会追加新发现的引文，已有记录和编号不变。去重靠摘录文字，所以改了引文要同步填 `replacement`（或改 `excerpt`），否则再扫会多出一条。扫描抓不全：没有注号的引文、作者间接转述的内容，通读时发现了就手工加记录，编号用"章号-下一个序号"。扫错的记成 `not_applicable`。

`audit/citations.json` 里每条记录的主要字段：

```json
{
  "id": "03-07",
  "file": "03_ch02.md",
  "anchor": "b045",
  "note": "7",
  "excerpt": "“红军每到一处，都发现群众冷淡而保留”",
  "status": "restored",
  "sources": [
    {"title": "毛泽东《井冈山的斗争》", "level": "web_transcript", "url": "https://...", "page": "", "accessed": "2026-10-08"}
  ],
  "replacement": "“红军每到一地，群众冷冷清清”",
  "research_note": "原注 7 实际引的是另一位领导人的评论，已在校注说明。",
  "next_action": ""
}
```

**状态**：

| `status` | 含义 | 正文是否保留 `【原文待核】` |
| --- | --- | --- |
| `not_reviewed` | 还没查 | 视初译而定 |
| `restored` | 找到中文原文或中译本，已替换 | 否 |
| `verified_original` | 找到外文原文，核对后自译 | 否 |
| `back_translated` | 用户授权，依可靠外文记录回译 | 否，校注写明是回译 |
| `partial` | 有部分证据或线索，原句未落实 | 是 |
| `searched_unresolved` | 查过但没落实 | 是 |
| `not_applicable` | 不是需要核查的引文 | 否 |

其他可选字段：来源里的 `localPath`、`sha256`（存档文件）；记录上的 `acceptance`（回译依据的用户授权）和 `markers`（这条对应几处待核标记，默认 1）。

**没有放待核标记的情况。** 间接转述或普通出处注，书目查到了、内容没核到，又不必在正文打标记的，记 `partial`，加 `"markers": 0`，并在 `research_note` 写明。

**回译只能在用户授权的范围内算落实。** 把授权原话和日期写进台账顶层的 `acceptances`。比如用户同意"BBC 英文记录对上之后可以回译"，这个授权不能自动扩大到其他英文转载。校注要写明是回译，不能称为恢复原句。

台账顶层还有 `access_limits`（用户告知的无权限数据库）和 `requests`（已提交的文献传递及其状态）。已经在等的就不要重复提。

## 每轮的做法

1. 挑一批：按来源分组效率最高（同一本书、同一份报纸的引文一起查）。
2. 查证：目标页、原文、版本、页码都确认，能存档的公开材料放到 `audit/sources/`（记录文件名和 SHA-256）。用户提供的文件原样保存，不改写。
3. 改译文：替换引文，去掉标记，必要时加章末校注（说明来源、差异）。
4. 校验：

   ```bash
   python <skill>/scripts/booktool.py audit-check .
   ```

   它会核对：状态合法；落实的条目有来源和证据级别；`replacement` 确实出现在对应章节；回译有授权；`【原文待核】` 的总数和台账一致。

5. 更新台账顶层的 `round` 和 `date`，写本轮报告 `audit/rounds/YYYY-MM-DD-roundN.md`：本轮查了哪些、升级了哪些、当前累计各状态的数量、还缺什么、下一步最具体的线索。写明实际阅读范围（目读了哪几页，哪些只是 OCR 筛查）。各轮的数量是累计快照，不能相加。

6. 给用户的材料请求要具体：刊名、期号、日期、页码、可能的馆藏位置，让用户能照着去申请。

## 和其他阶段的关系

- 引文核查放在润色之前。润色时不能改动已落实的引文，`polish-check` 会检查。
- 如果润色后又查到新引文，改完再跑一遍 `audit-check` 就行。
- 用户想停下来时可以停。待核的留着标记，完整版保留标记，无注释阅读版会去掉标记，书里也没有任何说明，所以交付时要告诉用户还有多少处待核。

## 小说和不重引用的书

没有多少引文的书，这一步可以很轻：诗歌、歌词、经典语录有现成中译的就用现成的，台账可以只记录几条。不用为了流程硬做。

## 完成标准

- 台账覆盖全部引文，没有 `not_reviewed`（或已向用户说明为什么不查了）；
- `audit-check . --final` 通过（不加 `--final` 时，未核查的条目不算错误）；
- 用户知道还有多少处待核、缺什么。
